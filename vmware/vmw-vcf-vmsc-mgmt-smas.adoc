== Configure a stretch cluster for a VCF management domain using SnapMirror Active Sync (SAN and NAS)
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ../media/

[.lead]
In this use case we outline the procedure to use ONTAP tools for VMware vSphere to configure a stretch cluster for a VCF management domain. This procedure includes deploying vSphere hosts and vCenter Server, installing ONTAP tools, protecting datastores with SnapMirror Active Sync, migrating VMs to protected datastores, and configuring supplemental storage.

image:vmw-vcf-vmsc-mgmt-smas-001.png[Stretch Cluster with ONTAP for VCF management domain]

Both Uniform and Non-uniform stretched cluster configurations are supported for SAN. In case of NAS, it is active-passive configuration with ONTAP 9.19.1.

[NOTE]
====
Host proximity settings are used with multipath configuration to ensure the optimal path selection for the storage traffic. The host proximity settings are configured on igroup in case of SCSI and subsystem in case of NVMe-oF. For example, in Uniform host access configuration, host has access to both storage systems in the stretched cluster. In multipath configuration, the optimal and non-optimal paths are configured based on the host proximity settings.
====

=== Scenario Overview

The stretch cluster solution can be implemented on default cluster or on additional cluster in VCF management or workload domains. ONTAP tools 10.6 supports datastore protection with SnapMirror active sync for VMFS datastores on iSCSI and FC protocols. ONTAP supports SnapMirror active sync for SAN (with iSCSI,FC, NVMe-oF) and NAS (NFS v3 and NFSv4.1). For SAN protocols the protection is performed at consistency group level while for NAS is performed at SVM level. The following diagram illustrates the stretch cluster solution for a VCF management domain with ONTAP tools for VMFS with FC.

image:vmware-vcf-asa-mgmt-stretchcluster-002.png[Stretch Cluster with ONTAP for VCF management domain]

.Principal storage on Management Domain
[%collapsible%open]
==== 

. Deploy VCF management domain with any supported protocol.
    .. For VMFS on FC and NFSv3, VCF Installer tool is used directly. In case of iSCSI, NVMe-oF, and NFSv4.1, it needs to be setup with vCenter and later use VCF installer tool to deploy the management domain. For more info, refer link:vmw-vcf-migrate.html[VCF Management Domain Deployment with iSCSI, NVMe-oF, and NFSv4.1]
. Deploy ONTAP tools for VMware vSphere
. Deploy SnapCenter Plugin for VMware vSphere (optional)
. Protect the datastore.
    .. For iSCSI and FC, ONTAP tools 10.6 or above is used to protect the datastores. In case of NVMe-oF and NFSv4.1, utilize system manager to protect the datastores. For reference, check the video demo below for NVMe/TCP and NFS. 




====

.Supplemental storage on Management Domain
[%collapsible%open]
==== 
Once the management domain is up and running, additional datastores can be created using ONTAP tools 10.6 or above and protected with SnapMirror active sync for iSCSI and FC. For NVMe-oF and NFS, check the video demo below for reference as the demo is performed on a workload domain, but the same steps can be followed for management domain as well. 

====
