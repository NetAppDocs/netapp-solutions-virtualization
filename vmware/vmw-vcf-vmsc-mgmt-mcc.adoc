= Configure a stretch cluster for a VCF management domain using MetroCluster
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ../media/

[.lead]
In this use case we outline the procedure to configure a stretch cluster for the VMware Cloud Foundation (VCF) management domain using ONTAP MetroCluster with FC or iSCSI or NVMe-oF or NFSv3 or NFSv4.1 as the primary datastore. VCF provides flexibility on deployment options based on your needs. VCF Installer tool is used to either deploy a new VCF management domain or convert an existing vSphere environment to a VCF management domain. In this document, we will focus on MetroCluster portion and point to other documentation based on the deployment steps.

image:vmw-vcf-vmsc-mgmt-mcc-001.png[VCF Management Domain with vMSC,width=500]

== Introduction

In this solution we will demonstrate how to implement Stretched VCF Management Domain with ONTAP MetroCluster as Principal Datastore. MetroCluster allows to deploy high availability solution for all workloads running on the ONTAP cluster. If need to deploy high availability solution specific to workloads, consider using SnapMirror active sync (SAN and NAS). SnapMirror active sync (SAN) works at consistency group level while SnapMirror active sync (NAS) works at SVM level. For more information, refer to link:vmw-vcf-vmsc-mgmt-smas.html[Configure a stretch cluster for a VCF management domain using SnapMirror Active Sync (SAN and NAS)].

== Prerequisites

This scenario requires the following components and configurations:

* Supported ONTAP MetroCluster configuration
* Storage virtual machine (SVM) configured with preferred storage protocol.
* Logical interface (LIF) has been created to carry storage traffic and is associated with the SVM.


== High-Level Overview

MetroCluster provides a high availability solution for workloads handled at aggregate level. SVM will be active on one of the fault domains in MetroCluster.

== Deployment Steps for Greenfield VCF Management Domain with MetroCluster

For Greenfield deployment (new deployment without any existing VCF components), VCF Installer tool is used to deploy the management domain. VMFS on FC and NFSv3 are supported in this scenario. 

In case of VMFS on FC, refer link:vmw-vcf-mgmt-principal-fc.html[VCF management domain with FC-based VMFS datastore on ONTAP as principal storage] for more information. For NFSv3, refer link:vmw-vcf-mgmt-principal-nfs.html[VCF management domain with NFSv3 datastore on ONTAP as principal storage] for more information.

== Deployment Steps for Brownfield VCF Management Domain with MetroCluster

A brownfield deployment is a scenario where you have an existing vSphere environment and you want to converge it as a VCF management domain.

For iSCSI, NVMe-oF, and NFSv4.1, it needs to be setup with vCenter (preferably with ONTAP tools) and later use VCF installer tool to converge in to the management domain. For more info, refer link:vmw-vcf-mgmt-vmfs.html[Convergence of vCenter with VMFS datastore] and link:vmw-vcf-mgmt-nfs.html[Convergence of vCenter with NFS datastore].
