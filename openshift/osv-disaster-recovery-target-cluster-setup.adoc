== Setup Disaster Recovery Target Cluster for OpenShift Virtualization. 

Note: All the following steps are performed on the target cluster, which is the cluster where the protected VM will failover to when a site outage occurs on the source cluster.

== Create AppVault using ONTAP S3
Set up the appvault on the target cluster by following the same steps as shown in the source cluster setup instructions. The appvault on the target cluster will be used to receive replicated data from the source cluster, and to restore that data when failover or failback operations are executed.

[source,yaml]
apiVersion: v1
# You can provide the keys either as stringData or base 64 encoded data
stringData:
  accessKeyID: "<access key id as obtained from ONTAP>"
  secretAccessKey: "<secret access key as obtained from ONTAP>"
#data:
  #accessKeyID: <base 64 encoded value of access key>
  #secretAccessKey: <base 64 encoded value of secret access key>
kind: Secret
metadata:
  name: appvault-secret
  namespace: trident-protect
type: Opaque

[source,yaml]
apiVersion: protect.trident.netapp.io/v1
kind: AppVault
metadata:
  name: ontap-s3-appvault
  namespace: trident-protect
spec:
  providerConfig: 
    s3:
      bucketName: oc-dr
      endpoint: <data lif to use to access S3>
      secure: "false"
      skipCertValidation: "true"
  providerCredentials:
    accessKeyID:
      valueFromSecret:
        key: accessKeyID
        name: appvault-secret
    secretAccessKey:
      valueFromSecret:
        key: secretAccessKey
        name: appvault-secret
  providerType: OntapS3

Ensure that ONTAP S3 vault is created and is in the Available state
[source, cli]
oc create -f app-vault-secret.yaml -n trident-protect
oc create -f app-vault.yaml -n trident-protect

== Create a Trident Protect app in this target cluster. 

This app will be used as the target app for replication. To create the app, follow the same steps as shown in the source cluster setup instructions to create an app custom resource. When creating the app CR, ensure that you select the appvault created in the previous step as the target vault for this app. Also ensure you have created a new namespace where the app will be replicated to, and select that namespace as the target namespace for this app.

[source,yaml]
----
# cat app.yaml
apiVersion: protect.trident.netapp.io/v1
kind: Application
metadata:
  creationTimestamp: null
  name: test-dest-app
  namespace: test-dr-ns-dest
spec:
  includedNamespaces:
  - namespace: test-dr-ns
----

Create AppMirrot Relationship between the source and the destination app. This can be done by creating a new AppMirror CR with the source app as the source and the destination app as the target. Once the AppMirror CR is created, you should start seeing the data from the source app being replicated to the destination app.
NOTE: Cluster and SVM peering and network connectivity between the source cluster and the ONTAP S3 endpoint must be in place for the replication to work.   

[source,yaml]
# application-mirror-relationship.yaml

apiVersion: protect.trident.netapp.io/v1
kind: AppMirrorRelationship
metadata:
  name: amr1
spec:
  desiredState: Established
  destinationAppVaultRef: ontap-s3-appvault
  destinationApplicationRef: dr-source-vm-failback
  namespaceMapping:
  - destination: test-dr-ns
    source: test-dr-ns-dest
  recurrenceRule: |-
    DTSTART:20240901T000200Z
    RRULE:FREQ=MINUTELY;INTERVAL=5
  sourceAppVaultRef: ontap-s3-appvault
  sourceApplicationName: test-dest-app
  sourceApplicationUID: "1b164123-83db-4f83-a47e-1bc4728af239"
  storageClassName: "sc-nas"

  When the AppMirror relationship is established, the most recent snapshot is transferred to the destination namespace. The PVC is created for the VM in the dr namespace, however, the VM pod is not yet created in the dr namespace.
